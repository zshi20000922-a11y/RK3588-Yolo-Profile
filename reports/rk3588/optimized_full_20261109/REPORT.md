# RK3588 INT8 YOLOv5 / YOLOv5u / YOLO26 优化后完整性能复测

日期：2026-11-09。模型为 YOLOv5n/s、YOLOv5un/us 与正式九输出 score-sum YOLO26n/s RKNN INT8。输入 640×640、batch=1、conf=0.25、IoU=0.45、max_det=100。本文把“1000 张自然图逐帧分项”与“固定 NV12 回放长测吞吐”分开报告，二者输入和测量目标不同，不混为同一 FPS。

## 结论摘要

- 优化后自然图 CPU 后处理均值：YOLOv5n/s 为 1.111/1.751 ms，YOLOv5nu/su 为 1.069/1.691 ms；正式 YOLO26n/s score-sum 为 2.380/0.638 ms。1 ms 目标目前只有 YOLO26s 在本次 1000 图样本中达到；n、v5s、v5su 仍未达到，v5n/v5nu 接近但略高于 1 ms。
- 单 context/Core 0 固定 NV12 回放三轮均值：v5n/s、v5nu/su、Y26n/s 分别为 51.35、33.67、42.93、27.42、32.54、21.22 FPS。
- 三 context 分别绑 Core 0/1/2 的总吞吐三轮均值：145.30、98.77、125.37、79.64、92.81、57.62 FPS。18 个三 context 运行的所有监控文件均观察到三个 NPU 核同时有负载；三核同时负载大于 50% 的样本中，各核范围为 51%–82%、中位数约 71%–72%。这是三个 context 同时处理不同帧，并不是一帧由三核协同计算。
- 六个模型回放吞吐轮间 CV 为 0.26%–2.27%；Y26n 三核 CPU 利用率偏高（约 70%–79%），是较明显的主机后处理/调度压力信号。
- 当前正式 Y26 的 RKNN SHA-256 与转换清单一致，已重新在同一 COCO val1000 上做低阈值 COCOeval：n/s AP50-95 为 0.36250/0.43819。早期后处理优化目录中的 Y26 JSONL 来自不同 SHA 的实验模型，不能作为当前正式模型的逐框一致性证据；v5/v5u 本次逐框 JSONL 与优化版存档完全一致。

## 实验控制与硬件状态

- RK3588 开发板经 USB ADB 连接，Linux `6.1.141`；RKNN Runtime/RGA 动态库来自板端既有部署。
- NPU 频率全程 1,000 MHz、DDR 1,560 MHz；正式运行监测温度 29.6–35.2°C。CPU governor 为 schedutil、DDR governor 为 dmc_ondemand，沿用板端原设置、没有改动 governor；因此 CPU 频率动态变化已记录，不宣称锁频测试。
- 所有模型均来自板端文件并记录 SHA；NPU 以 `rknn_set_core_mask` 显式绑核。单 context 为 Core 0；throughput 模式创建三个 context 分别绑定 0/1/2。每轮 100 帧预热，之后至少 3,000 帧且至少 60 秒。每种模型/模式三轮，顺序轮换/反向交错。
- 回放模式重复使用预载的 1920×1080 NV12 DMA buffer，排除文件/JPEG 读取与相机采集；RGA 预处理、NPU、输出同步、CPU 后处理均在帧级 CSV 中计时。程序端墙钟总帧数/秒数用于报告回放吞吐。
- 自然图分项使用同一 COCO val2017 1000 图有序 NV12 清单，单 context/Core 0，每个模型各处理该集合一次；板端与本机的 1000 个 image_id、尺寸及顺序完全相同；逐个核对的 1000 个 NV12 文件 SHA-256 全部匹配（1000/1000）。板端清单和逐帧 SHA 列表随结果归档。

## 固定 NV12 回放：三轮稳定吞吐

FPS 为各轮程序实际处理帧数/运行秒数；`均值 ± 标准差` 以三轮 FPS 计算，CV=`std/mean`。CPU 为 benchmark 进程 `getrusage` 的用户+系统 CPU 时间/墙钟时间，不是整机总 CPU 百分比。

| 模型 | 单 context/Core 0 三轮 FPS | 均值 ± std，CV | CPU 均值 | 三 context/Core 0,1,2 三轮总 FPS | 均值 ± std，CV | CPU 均值 | 三路/单路吞吐比 |
|---|---|---:|---:|---|---:|---:|---:|
| YOLOv5n | 52.03 / 50.94 / 51.08 | 51.35 ± 0.59，1.16% | 22.8% | 146.10 / 144.30 / 145.50 | 145.30 ± 0.92，0.63% | 71.1% | 2.83× |
| YOLOv5s | 34.06 / 33.66 / 33.28 | 33.67 ± 0.39，1.17% | 19.0% | 98.83 / 98.49 / 98.98 | 98.77 ± 0.25，0.26% | 45.9% | 2.93× |
| YOLOv5nu | 43.04 / 42.88 / 42.88 | 42.93 ± 0.10，0.22% | 21.4% | 125.52 / 124.34 / 126.25 | 125.37 ± 0.96，0.77% | 60.7% | 2.92× |
| YOLOv5su | 27.58 / 27.30 / 27.38 | 27.42 ± 0.14，0.51% | 17.8% | 80.20 / 79.60 / 79.12 | 79.64 ± 0.54，0.68% | 44.7% | 2.90× |
| YOLO26n score-sum | 32.81 / 32.55 / 32.25 | 32.54 ± 0.28，0.86% | 27.8% | 94.33 / 93.68 / 90.40 | 92.81 ± 2.11，2.27% | 73.6% | 2.85× |

Core0/1/2 的同时活动由 `/sys/kernel/debug/rknpu/load` 采样证实。三 context 是并行多帧吞吐，不等于单帧时延降低到三分之一，也不等于摄像头能持续输出该帧率。Y26n 三核的 FPS CV=2.27%，低于 5% 验收线但高于其他模型，且 CPU 利用率上升到 78.7%；建议部署前再做长时热稳定复测。

## 固定 COCO val1000：优化后分阶段端到端 Profile

以下来自每模型 1000 张不同图、单 context/Core 0；单位 ms。P50/P95/P99 为逐帧分布分位数。E2E 为 NV12 DMA frame 进入处理后到检测列表返回，含 RGA、NPU、输出同步和 CPU 后处理；不含磁盘读取、JPEG 解码、摄像头采集/曝光、显示或存盘。Y26 raw-head 是 one-to-many，仍执行 CPU 解码和 NMS，不是 NMS-free。

| 模型 | RGA mean | NPU mean | 输出同步 mean | CPU 后处理 mean ± std / P50 / P95 / P99 | E2E mean ± std / P50 / P95 / P99 | 折算 FPS |
|---|---:|---:|---:|---:|---:|---:|
| YOLOv5n | 0.608 | 15.620 | 0.281 | **1.111 ± 0.716 / 0.738 / 2.151 / 2.699** | 18.024 ± 2.193 / 18.280 / 21.966 / 23.391 | 55.48 |
| YOLOv5s | 0.781 | 25.071 | 0.429 | **1.751 ± 0.643 / 1.770 / 2.805 / 3.391** | 28.636 ± 1.685 / 28.777 / 30.876 / 33.398 | 34.92 |
| YOLOv5nu | 0.686 | 19.047 | 0.283 | **1.069 ± 0.827 / 1.001 / 2.500 / 3.387** | 22.062 ± 2.267 / 22.006 / 25.975 / 28.519 | 45.33 |
| YOLOv5su | 0.806 | 31.977 | 0.438 | **1.691 ± 0.900 / 1.464 / 3.466 / 4.821** | 36.127 ± 1.830 / 35.940 / 39.258 / 41.188 | 27.68 |
| YOLO26n score-sum | 0.781 | 24.369 | 0.297 | **2.380 ± 0.680 / 2.619 / 2.727 / 2.839** | 29.305 ± 2.449 / 29.375 / 33.201 / 36.896 | 34.12 |
| YOLO26s score-sum | 0.807 | 42.274 | 0.368 | **0.638 ± 0.096 / 0.645 / 0.722 / 0.761** | 45.657 ± 2.206 / 45.358 / 50.398 / 53.256 | 21.90 |

| 模型 | decode mean | NMS mean | 每图 score gate 平均通过 | 最终检测/图平均 |
|---|---:|---:|---:|---:|
| YOLOv5n | 1.024 | 0.078 | 76 | 13.56 |
| YOLOv5s | 1.553 | 0.182 | 102 | 21.36 |
| YOLOv5nu | 1.005 | 0.054 | 39 | 8.89 |
| YOLOv5su | 1.572 | 0.104 | 53 | 14.43 |
| YOLO26n score-sum | 2.351 | 0.017 | **6,404** | 4.45 |
| YOLO26s score-sum | 0.602 | 0.023 | **7** | 6.46 |

这解释了当前正式 score-sum 版本里 Y26n 后处理长于 Y26s：本次 1000 图上，n 分支的 `score_sum` 门控平均放行约 6,404 个格点，之后仅约 4.6 个格点通过类别分数过滤；s 分支的门控只放行约 7 个格点。该 profile 直接表明 n 分支门控的候选筛除能力较弱，是后处理耗时的强相关因素；但还需结合模型输出量化属性/score_sum 分布核验成因，不能仅由计数断言是 NMS 导致。实际 NMS 均值只有 0.017 ms，瓶颈在解码/分数扫描路径。

阶段均值之和与 E2E mean 的差为约 0.40–1.57 ms。E2E 使用 `capture_to_result` 端到端时钟；各阶段计时边界独立，包含调用/同步及调度成本，因此不能要求阶段值严格相加。完整逐帧 CSV 保留供审计。

前处理的 `RGA mean` 是从 NV12 DMA fd 到 RGB RKNN 输入 tensor 的同步 `improcess` 聚合时间，覆盖 letterbox 几何计算、NV12→RGB、resize/padding；当前实现把它们放在一次 RGA API call 内，不能用现有计时器将 RGA 内部色彩转换与 resize 再拆成各自耗时。DMA 回放的 `copy_ms=0`，输入复制在计时前完成；这不是摄像头采集端到端实测。

所有模型低阈值输出均含负宽高/零面积退化框，统一 COCOeval 前过滤；六模型 NaN/Inf 均为 0，类别 ID 越界均为 0。PT 基线使用本轮统一后端报告中的重新验证值；v5 legacy 验证器输出精度仅 0.001，v5u PT 基线存在对应关系疑点，故相关 delta 只作参考。当前正式 Y26 模型 hash：n `72845062d5a3bfdb5778ce4beef71f1623ca6ff8e2662d277946bbe91966f637`，s `c9b1705a9d24a8b4c48dd83aa5fa2490b0c09eb81e6aa5846e961373e6411491`。两者与正式转换清单、板端文件相符。旧 `postprocess_optimization/optimized_conf025` 中 Y26 JSONL 采用不同 SHA 的早期实验权重，不能作为正式模型一致性基线。

低阈值的 v5/v5u 输出是本轮优化后代码在板端对相同 1000 图重新推理并统一 COCOeval 的结果；PT 侧数值与统一后端报告的重新验证值对齐。完整十模型表见 `../unified_same_dataset_rknn/REPORT.md`。

## 后处理优化判断

- v5n/v5u-n 约 1.07–1.11 ms，接近但严格说没有达到 1 ms；v5s/v5su 约 1.69–1.75 ms。
- 当前正式 Y26n 2.38 ms，仍明显高于目标；Y26s 为 0.64 ms。Y26n 的分数门控通过量是 s 的约 900 倍，而 NMS 用时很少。应优先核查 n 输出的 score-sum 量化尺度、零点/输出范围，以及按量化值进行的阈值门控；必须在保持 conf、IoU、max_det 和逐图输出一致的条件下尝试修复。
- 另一条 score-max 模型曾在独立 COCO128 校准设置下测出更低后处理，但它是单独导出模型，不能替代正式 score-sum 精度表或当前三轮回放排名。

## 数据文件

- `raw`：`latency/<model>/<model>_r[1-3].csv` 与 `throughput/<model>/<model>_r[1-3].csv`，逐帧 RGA/NPU/同步/CPU 后处理/E2E 数据。
- `*_monitor.csv`：温度、CPU/DDR/NPU 频率、NPU 每核利用率和系统 loadavg；`*_log` 与 `*_command.txt` 记录运行结果、参数。
- `natural/*_timings.csv`、`natural/*.jsonl`：固定 COCO 1000 图逐帧分项/部署阈值检测；`natural/yolo26*_map.jsonl` 为 AP 低阈值输出。
- `input_list_board.txt`、`natural/board_nv12_sha256.txt`：板端固定图像清单及 1000 帧 NV12 内容哈希。
- `natural/yolo26_current_map.csv`：当前正式 Y26 的重新 COCOeval 指标。
- `natural/quality_metrics.csv`：六模型当前优化后 RKNN 在固定 1000 图上的统一 COCOeval 指标及分项统计。
- `summary.csv`、`natural_stage_summary.csv`：可复算的三轮回放和 1000 图分项统计汇总。
- `model_hashes.csv`：六个模型与 manifest 的本机/板端 SHA-256 一致性审计。
- `environment.json`：内核/设备和输入清单记录；板端清单与仓库清单路径前缀不同，image_id 顺序相同。
- 可复现脚本：`../../../tools/run_optimized_rk3588_matrix.py`（三轮回放）、`../../../tools/run_optimized_natural_profile.py`（conf=0.25 分项）、`../../../tools/run_optimized_coco_map.py`（conf=0.001 AP 预测）、`../../../tools/evaluate_coco_jsonl.py`（统一 COCOeval）。板端程序由 `tools/rk3588_yolo_benchmark.cc` / `tools/rk3588_yolo_quality.cc` 交叉编译生成。
